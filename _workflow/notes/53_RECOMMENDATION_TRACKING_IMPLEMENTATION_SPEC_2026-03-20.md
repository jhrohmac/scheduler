# 추천 종목 관리/추적 구현 명세서

기준일: 2026-03-20  
문서 성격: AI Agent 구현용 확정 명세  
선행 문서: `52_RECOMMENDATION_TRACKING_DESIGN_2026-03-20.md`

## 0. 문서 목적

이 문서는 AI Agent 또는 개발자가 본 문서만 읽고도, 추가 질의 없이 동일한 결과를 구현할 수 있도록 작성한 확정 구현 명세서다.

이 문서에서 정의한 항목은 모두 "결정 완료" 상태로 간주한다.

- 테이블명/컬럼명
- Java 클래스명/패키지명
- MyBatis Mapper 파일명/namespace/id
- Spring bean 등록 위치
- API URL/요청 파라미터/응답 구조
- 배치 수행 순서
- 수익률/확률/매도 가이드 계산 규칙
- 기본값/예외 처리 규칙

명시되지 않은 부분은 임의 해석하지 말고 기존 프로젝트 관례를 따른다.

## 1. 구현 목표

아래 6개 요구를 현재 프로젝트 스타일로 정확히 구현한다.

1. 추천 종목을 관심종목으로 저장
2. 추천 종목의 정보 저장
3. 추천 종목의 정보를 토대로 추적 확인
4. 추천 종목을 관심종목에 등록한 날짜 이후 상승/하락 추적
5. 추천 종목 정보를 토대로 매수 했을때 일자별 성공 확률 계산
6. 매수한 종목을 매일 추적 업데이트 하여 매도 시점 표시

## 2. 구현 원칙

### 2-1. 데이터 정본 원칙

- 추천 결과 정본: `TB_REC_SIGNAL`
- 거래일 정본: `TB_TRADE_CALENDAR`
- 일봉 가격 정본: KIS API 응답을 메모리에서 사용하며 필요 시 추적 결과만 저장
- 관심종목 화면 정본: `TB_S_INTEREST_WATCHLIST`
- 추천 저장/추적 정본: 이번 작업에서 추가할 `TB_S_RECO_PICK*`
- 보유종목 정본: `TB_S_POSITION*`

### 2-2. 평가 기준 원칙

- 공식 성과 계산은 반드시 KIS 일봉 기준으로 처리
- 실시간 현재가는 UI 표시용 참고값으로만 사용
- D+N 계산은 달력일이 아니라 거래일 기준
- 등록 성과와 매수 성과는 서로 다른 anchor 로 계산

### 2-3. 구현 범위 원칙

이번 작업 범위에 포함:

- 추천 저장 API
- 추천 저장 이력 테이블
- 일별 추적 테이블
- Horizon 평가 테이블
- 매수 등록 시 추천-포지션 연결
- 매일 포지션 매도 가이드 계산
- 성공 확률 집계 API

이번 작업 범위에서 제외:

- 자동 주문 실행
- 실시간 매도 자동 트리거
- 머신러닝 모델 학습
- Notion 연동

## 5-1. `TB_S_RECO_PICK`

목적:

- 추천 종목을 사용자가 watchlist 로 저장한 행위와 당시 추천 스냅샷을 보관

정확한 DDL은 아래 기준으로 생성한다.

```sql
CREATE TABLE TB_S_RECO_PICK (
    PICK_ID             NUMBER GENERATED BY DEFAULT AS IDENTITY,
    SOURCE_TYPE         VARCHAR2(30)    DEFAULT 'REC_SIGNAL_V110' NOT NULL,
    SOURCE_BASE_DT      DATE            NOT NULL,
    SOURCE_MKT_CD       VARCHAR2(10)    NOT NULL,
    STK_CD              VARCHAR2(20)    NOT NULL,
    STK_NM              VARCHAR2(100),
    LISTING_MARKET      VARCHAR2(20),
    WATCH_GROUP_ID      VARCHAR2(30)    NOT NULL,
    PICK_STATUS         VARCHAR2(20)    DEFAULT 'WATCH' NOT NULL,
    REC_RANK            NUMBER,
    REC_YN              CHAR(1)         DEFAULT 'Y' NOT NULL,
    REC_GRADE           VARCHAR2(5),
    REC_REASON          VARCHAR2(1000),
    GOLDEN_YN           CHAR(1),
    MON_UP_YN           CHAR(1),
    MON_CHG_RATE        NUMBER(18,4),
    TREND_STRENGTH      NUMBER(18,4),
    AVG_TRD_VAL_20      NUMBER(18,0),
    REC_ANCHOR_PRICE    NUMBER(18,4)    NOT NULL,
    WATCH_ANCHOR_PRICE  NUMBER(18,4)    NOT NULL,
    WATCH_SAVED_AT      DATE            DEFAULT SYSDATE NOT NULL,
    FIRST_BUY_DATE      DATE,
    FIRST_BUY_PRICE     NUMBER(18,4),
    FIRST_BUY_QTY       NUMBER,
    POSITION_ID         NUMBER,
    ENTRY_RULE_CODE     VARCHAR2(30),
    SNAPSHOT_JSON       CLOB,
    LAST_TRACK_DT       DATE,
    CREATE_USER         VARCHAR2(50),
    CREATE_DATE         DATE            DEFAULT SYSDATE NOT NULL,
    MODIFY_DATE         DATE            DEFAULT SYSDATE NOT NULL,
    CONSTRAINT PK_TB_S_RECO_PICK PRIMARY KEY (PICK_ID)
);

CREATE INDEX IX_TB_S_RECO_PICK_01 ON TB_S_RECO_PICK (STK_CD, WATCH_SAVED_AT);
CREATE INDEX IX_TB_S_RECO_PICK_02 ON TB_S_RECO_PICK (PICK_STATUS, WATCH_SAVED_AT);
CREATE INDEX IX_TB_S_RECO_PICK_03 ON TB_S_RECO_PICK (POSITION_ID);
CREATE INDEX IX_TB_S_RECO_PICK_04 ON TB_S_RECO_PICK (SOURCE_BASE_DT, SOURCE_MKT_CD, STK_CD);
```

컬럼 규칙:

- `REC_ANCHOR_PRICE` 는 추천 기준가
- `WATCH_ANCHOR_PRICE` 는 사용자가 저장한 시점 기준가
- `FIRST_BUY_*` 는 최초 매수 기준
- `PICK_STATUS` 허용값: `WATCH`, `BOUGHT`, `CLOSED`, `CANCELLED`
- `ENTRY_RULE_CODE` 허용값: `REC_CLOSE`, `PULLBACK_MA20`, `BREAKOUT_20`, `MANUAL`

## 5-5. `TB_S_POSITION` 확장

이번 작업에서 아래 컬럼을 추가한다.

```sql
ALTER TABLE TB_S_POSITION ADD (
    SOURCE_PICK_ID         NUMBER,
    BUY_DATE               DATE,
    TARGET_PRICE           NUMBER(18,4),
    STOP_PRICE             NUMBER(18,4),
    TP1_PRICE              NUMBER(18,4),
    SELL_GUIDE_STATE       VARCHAR2(20),
    LAST_SELL_SIGNAL_CODE  VARCHAR2(30),
    LAST_TRACK_DATE        DATE
);
```

기존 제약 보정 규칙:

- 기존 `UX_TB_S_POSITION_01 (STOCK_GROUP, STOCK_CODE)` 는 유지하지 않는다.
- 이번 작업에서 아래로 교체한다.

```sql
DROP INDEX UX_TB_S_POSITION_01;
CREATE UNIQUE INDEX UX_TB_S_POSITION_01 ON TB_S_POSITION (STOCK_GROUP, STOCK_CODE, CLOSE_FLAG);
```

이유:

- 기존 인덱스는 청산 이력이 있는 종목을 같은 그룹에서 재매수할 수 없게 만든다.
- 추천 추적/재진입 매수 흐름을 허용하려면 `CLOSE_FLAG` 를 포함해야 한다.

`SELL_GUIDE_STATE` 허용값:

- `HOLD`
- `TP1_DONE`
- `TRAILING`
- `SELL_READY`
- `STOP_LOSS`
- `CLOSED`

## 11. 계산 규칙

## 11-1. 거래일 계산 규칙

`TradeDateService` 에 아래 메서드를 추가한다.

```java
public String addTradingDays(String baseDt, String marketGroup, int offset) throws Exception;
public int diffTradingDays(String fromDt, String toDt, String marketGroup) throws Exception;
public List<String> selectTradingDatesBetween(String fromDt, String toDt, String marketGroup) throws Exception;
```

규칙:

- `baseDt` 포함을 0일로 간주
- 다음 거래일이 D+1
- `offset = 5` 이면 기준일 다음 5번째 거래일

DAO 호출 규칙:

- `addTradingDays()` 는 `TradeDateDao.selectTradingDateByOffset()` 사용
- `diffTradingDays()` 는 `TradeDateDao.selectTradingDaysBetween()` 사용
- `selectTradingDatesBetween()` 는 `TradeDateDao.selectTradingDateListBetween()` 사용

## 11-2. 수익률 계산 공식

```text
returnPct = ((closePrice / anchorPrice) - 1) * 100
mfePct    = ((maxHigh / anchorPrice) - 1) * 100
maePct    = ((minLow / anchorPrice) - 1) * 100
```

소수 처리:

- DB 저장 전 `Math.round(value * 10000d) / 10000d`

anchor 선택:

- 추천 성과: `REC_ANCHOR_PRICE`
- 등록 성과: `WATCH_ANCHOR_PRICE`
- 매수 성과: `FIRST_BUY_PRICE`

## 11-3. 상승/하락 판정

```text
if closePrice > previousClose -> UP
if closePrice < previousClose -> DOWN
else FLAT
```

첫 거래일은 `closePrice vs anchorPrice` 로 비교

## 11-4. 초기 목표가/손절가/TP1 계산 규칙

`registerBuy()` 에서 아래 규칙을 적용한다.

기본 룰:

- `targetPrice = buyPrice * 1.10`
- `stopPrice = buyPrice * 0.93`
- `tp1Price = buyPrice * 1.05`

단, `entryRuleCode = BREAKOUT_20` 이면:

- `targetPrice = buyPrice * 1.12`
- `stopPrice = buyPrice * 0.95`
- `tp1Price = buyPrice * 1.06`

`entryRuleCode = PULLBACK_MA20` 이면:

- `targetPrice = buyPrice * 1.08`
- `stopPrice = buyPrice * 0.95`
- `tp1Price = buyPrice * 1.04`

초기 구현에서는 복잡한 ATR 기반 계산을 하지 않는다.

## 11-5. TP1/손절 판정 규칙

하루 기준:

- `HIGH_PRICE >= TP1_PRICE` 이면 `TP1_HIT_YN = Y`
- `LOW_PRICE <= STOP_PRICE` 이면 `STOP_HIT_YN = Y`

동일 일자에 둘 다 충족 시 우선순위:

1. `STOP_HIT_YN = Y`
2. `TP1_HIT_YN = Y`

이유:

- 일중 순서를 알 수 없으므로 보수적으로 손절 우선 처리

## 11-6. 승률 판정 규칙

`TB_S_RECO_PICK_EVAL.WIN_YN` 계산 규칙:

- `RETURN_PCT > 0` 이면 `Y`
- 아니면 `N`

## 11-7. 매도 가이드 판정 규칙

포지션 일별 최신 row 기준으로 아래 우선순위를 적용한다.

1. `LOW_PRICE <= STOP_PRICE`
   - `SELL_SIGNAL_CODE = STOP_LOSS`
   - `SELL_GUIDE_STATE = STOP_LOSS`
2. `HIGH_PRICE >= TP1_PRICE` 이고 `SELL_GUIDE_STATE != TP1_DONE`
   - `SELL_SIGNAL_CODE = TP1`
   - `SELL_GUIDE_STATE = TP1_DONE`
3. `TP1_DONE` 이후 `CLOSE_PRICE < MA20_PROXY`
   - `SELL_SIGNAL_CODE = TRAILING_EXIT`
   - `SELL_GUIDE_STATE = SELL_READY`
4. `RETURN_FROM_BUY_PCT <= -7`
   - `SELL_SIGNAL_CODE = STOP_LOSS`
   - `SELL_GUIDE_STATE = STOP_LOSS`
5. `HOLD_DAY_NO_FROM_BUY >= 20` 이고 `RETURN_FROM_BUY_PCT < 2`
   - `SELL_SIGNAL_CODE = TIME_EXIT`
   - `SELL_GUIDE_STATE = SELL_READY`
6. 나머지
   - `SELL_SIGNAL_CODE = NONE`
   - `SELL_GUIDE_STATE = HOLD`

`MA20_PROXY` 규칙:

- 현재 구현에서는 KIS 일봉 20개 종가 단순이평을 메모리 계산

## 11-8. 확률 집계 공식

`VW_S_RECO_PICK_STATS` 계산 규칙:

```text
sampleCnt      = COUNT(*)
winRate        = SUM(CASE WHEN win_yn='Y' THEN 1 ELSE 0 END) / COUNT(*) * 100
tp1Rate        = SUM(CASE WHEN tp1_hit_yn='Y' THEN 1 ELSE 0 END) / COUNT(*) * 100
stopRate       = SUM(CASE WHEN stop_hit_yn='Y' THEN 1 ELSE 0 END) / COUNT(*) * 100
avgReturnPct   = AVG(return_pct)
avgMfePct      = AVG(mfe_pct)
avgMaePct      = AVG(mae_pct)
```

표본 수 표시 규칙:

- `sampleCnt < 20` 인 경우 UI 에서 `lowConfidenceYn = Y` 로 표시할 수 있도록 응답 map 에 포함 가능
- 단, 이번 작업에서는 view 컬럼에 포함하지 않고 service 에서 파생 계산

- 동일 pick 중복 매수 등록 차단
- dailyTrack 목록 조회 가능
- probability 조회 가능

## 17-3. 계산

- 20거래일 미도달 시 `CALC_STATUS = PENDING`

- 포지션 이벤트에 매도 가이드 메시지 적재

## 20. AI Agent 구현 지시

AI Agent 는 아래 규칙을 반드시 따른다.

1. 본 문서의 파일명/클래스명/메서드명을 임의 변경하지 않는다.
2. 신규 API 응답은 `ResponseHandler.sendResponse()` 포맷을 사용한다.
3. 신규 Mapper 는 `RecPickMapper.xml` 하나에 우선 작성한다.
4. DB 스키마 적용 전 기존 테이블/컬럼명을 재확인하되, 본 문서의 명세를 우선한다.
5. 계산 로직은 문서에 정의된 공식과 우선순위를 그대로 따른다.
6. 불명확한 로직을 추론하지 말고, 문서에 없는 고도화는 추가하지 않는다.

이 문서는 "정확히 구현 가능한 수준"을 목표로 확정되었으므로, 추가 기획 없이 바로 구현 단계로 진입해도 된다.
