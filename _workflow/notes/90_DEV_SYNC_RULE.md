# 개발 동기화 규칙 (Source ↔ Canvas ↔ Notion)

이 문서는 프로젝트 소스와 `_workflow/canvas/MASTER_WORKFLOW.canvas`를 항상 같은 구조로 유지하기 위한 강제 운영 규칙이다.
공식 캔버스는 `MASTER_WORKFLOW.canvas` 하나만 사용한다.
추가 설명, 구조 메모, 삭제된 캔버스 이관 내용은 `_workflow/notes/MASTER_WORKFLOW_NOTE.md` 에 정리한다.

## 1. 강제 원칙 (요청사항 반영)

1. 프로젝트 소스와 워크플로우 캔버스의 구성은 동일해야 한다.
2. 소스를 변경하면 같은 작업 단위에서 캔버스도 함께 수정해야 한다.
3. 소스의 등록/수정/삭제는 캔버스에도 같은 등록/수정/삭제로 반영해야 한다.
4. 캔버스 노드 ID로 수정 요청이 들어오면, 연결된 소스 경로를 즉시 식별해야 한다.
5. 소스 변경 결과는 반드시 캔버스 ID 기준으로 보고해야 한다.

## 2. SoT(기준)와 충돌 처리

- 구현 사실 SoT: `src/`, `webapp/`, `db/`의 실제 소스/SQL
- 구조/연결 SoT: `_workflow/canvas/MASTER_WORKFLOW.canvas`
- 진행 상태 SoT: 노션 `MASTER WORKFLOW DB`
- 보조 설명 SoT: `_workflow/notes/MASTER_WORKFLOW_NOTE.md`

충돌 시 처리 순서:
1. 소스 구현 사실을 먼저 확정한다.
2. 캔버스 연결/구조를 소스 사실에 맞춘다.
3. 노션 상태/우선순위를 마지막에 정렬한다.

## 3. 작업 단위 규칙 (연속성/오염 방지)

- 한 작업은 기본적으로 대표 캔버스 ID 1개(`WF-*`)를 가진다.
- 하나의 커밋/작업 단위에 서로 무관한 노드 ID를 섞지 않는다.
- 기능 수정과 구조 리팩터링을 한 작업에 혼합하지 않는다.
- 캔버스 반영이 끝나기 전에는 작업을 완료로 간주하지 않는다.
- 임시 코드, 실험 스니펫, 사용되지 않는 파일은 당일 정리한다.

## 4. 공통 ID 규칙

- 캔버스, 노션, 문서, 변경 보고에서 동일한 캔버스 ID를 사용한다.
- 권장 형식: `WF-<영역>-<기능>` 또는 기존 코드 체계(`2-4`, `3-8`)와 호환되는 `WF-*`.
- 신규 기능은 소스 작성 전에 캔버스 노드 ID를 먼저 부여한다.
- 보조 캔버스는 새로 만들지 않는다.

## 5. 변경 타입별 동기화 절차

### A. 소스 등록(신규)
1. 캔버스에 신규 노드 생성(상태 `⬜`).
2. `_workflow/notes/92_SOURCE_SYNC_MATRIX.md`에 노드-소스 앵커 등록.
3. 소스 파일/DDL/설정 추가.
4. 노션 항목 생성 후 상태 정렬.

### B. 소스 수정(기능 변경)
1. 대상 노드 ID 확정.
2. 소스 수정.
3. 캔버스 노드 설명/연결/체크포인트 동기화.
4. 노션 상태와 체크리스트 업데이트.

### C. 소스 삭제(기능 폐기)
1. 캔버스에서 동일 노드를 `삭제` 또는 `deprecated` 상태로 전환.
2. 연결 edge 정리.
3. 소스/SQL/설정 삭제.
4. 삭제 사유와 대체 경로를 노션/문서에 기록.

## 5-1. 사전 승인 게이트 (필수)

프로젝트 소스/캔버스를 수정할 때는 아래를 먼저 설명하고 승인 후 진행한다.

1. 변경 방향(무엇을 왜 바꾸는지)
2. 대상 Canvas ID
3. 영향 범위(소스/캔버스/노션)
4. 변경 타입(`ADD`/`MODIFY`/`DELETE`)

승인 전에는 탐색, 영향도 분석, 매핑 정리까지만 수행하고 실제 파일 수정은 하지 않는다.

## 6. 노드 ID 입력 시 즉시 추적 규칙

노드 ID 기반 요청이 들어오면 아래 순서로 즉시 매핑한다.

1. `_workflow/notes/92_SOURCE_SYNC_MATRIX.md`에서 노드 ID의 앵커 경로 확인
2. 소스 전체 검색으로 실제 영향 경로 보강
3. 결과를 `Canvas ID + 관련 파일 + 변경 타입`으로 보고

권장 검색 명령:

```bash
rg -n "<CANVAS_ID>|핵심키워드" _workflow src webapp db
```

## 7. 변경 보고 표준 포맷

모든 수정/등록/삭제 보고는 아래 형식을 따른다.

```text
Canvas ID: WF-...
Change Type: ADD | MODIFY | DELETE
Source Files:
- <absolute path>
- <absolute path>
Canvas Sync:
- MASTER_WORKFLOW.canvas 노드/연결 반영 여부
- 92_SOURCE_SYNC_MATRIX.md 앵커 반영 여부
```

## 8. 상태 동기화 기준

- `⬜ 미착수`: 캔버스/노션 등록만 있고 소스 미반영
- `🟡 진행중`: 소스 또는 캔버스 중 일부만 반영
- `✅ 완료`: 소스 + 캔버스 + 노션이 모두 일치
- `⚠️ 운영주의`: 기능은 있으나 운영 리스크가 남음

## 9. 작업 종료 게이트 (DoD)

아래 5개가 모두 `Yes`여야 종료한다.

1. 소스 변경 목록이 캔버스 노드 ID로 매핑되었는가
2. `_workflow/canvas/MASTER_WORKFLOW.canvas`가 같은 변경을 반영했는가
3. `_workflow/notes/92_SOURCE_SYNC_MATRIX.md`가 최신 앵커를 반영했는가
4. 필요 시 `_workflow/notes/MASTER_WORKFLOW_NOTE.md`에 보조 설명이 정리되었는가
5. 노션 상태가 실제 코드 상태와 일치하는가
6. 변경 보고에 `Canvas ID`가 누락되지 않았는가
